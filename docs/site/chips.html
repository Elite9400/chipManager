What each state means
StateMeaning
ProposedAn agent suggested work. Nothing has started.
QueuedApproved work waits for dependencies, a parallel slot, or the Codex lane. Ready work can skip this state.
StartingThe action is reserved with an attempt token, so two panels cannot start it twice.
StartedA session is working.
Waiting for childrenA director has reported attesa-figli. It waits without using a parallel slot; resuming counts as a re-plan.
DeliveredThe result is ready. A process ending does not prove a merge.
CompletedThe linked registry task is merged, or you used Mark done.
FailedA start or run failed. Read the reason before retrying.
DiscardedWithdrawn from the queue; the owner can undo the discard.

Delivered is not done. Automatic closing needs a registry task matched by branch and issue. Without the registry, or in a shared checkout, inspect the result and use Mark done.

Dependencies wait for completion

dipende lists existing chip IDs whose results must be completed first. Delivery alone does not release ordinary dependencies. Depend only on merged files or data that the next task needs; independent work can run in parallel.

Missing, discarded, or invalid dependencies block the start with a reason. Queued work can start when its conditions become ready. Chain steps use dopoConsegna instead: delivery with a versioned artefact releases the next step. Each step still needs approval. Follow a text chain.

Start one or a batch

Start controls
ControlWhat it does
StartChecks and starts this chip, or queues it if a dependency or capacity must wait.
Start nextChooses the first eligible chip in the current launch plan.
Start allPreviews starts, queued work, and blocks; asks for confirmation before launching the batch.

Rules are checked again at launch. Weights and lane scoring can reorder a bulk plan; ties keep your order. Dependencies, reviewer requirements, and concurrency limits still apply. Closing a confirmation without choosing starts nothing.

Start uncertain? Check the existing session or attempt before retrying. A missing launch reply is not proof that nothing started; the launcher does not start a second worker as a fallback.

Choose where it runs

Use Details → How the session starts → Where, or select chips and use the destination bar. Unavailable choices show their reason.

Destinations
WhereExecution & costLimits
On this computerA desktop session, or a CLI worker in its own worktree. Uses plan limits.Sensitive work stays here. CLI has no fork, cloud, or shared-folder launch.
In the cloudA new Claude cloud session from a pushed GitHub branch. Uses plan limits.Desktop route; fresh only. Title + brief only, up to 1,500 characters. No sensitive work, local-data patterns, Codex, or auditor.
Here on API credits (Claude)Headless Claude on this computer in a separate worktree. Bills API credits.Key, account budget, and cap required. One API run per machine; no sensitive work or fork. Commits locally, never pushes; review follows delivery.

Chain steps stay local. API-lane and cloud chain steps are blocked in 2.2.0. Children also inherit their director’s destination restriction; starting a parent never approves its children.

Local means the session runs here. Claude or Codex still uses its service. It does not mean offline inference. See external text writers.

A worktree is a separate checkout and branch. Keep it enabled unless you have a reason to share a checkout. Worktrees are not deleted automatically.

API cost is separate

The API lane reserves the run’s cap against both the account budget and any project month limit. An uncertain outcome counts the whole reserved cap. Actual spending can exceed the per-run cap slightly; the Console workspace spend limit is the hard cap. Set up API credits.
