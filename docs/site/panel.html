Read the panel.

Three views answer three questions: what needs you, how much capacity is left, and how work should run.

Start at the header

The ▣ chipManager brand is followed by the project and version. Refresh updates the view; Open board appears when the local board is ready.

The summary counts work in progress, work waiting for you, and chips to start. Provider usage comes from the fullest relevant limit. Old measurements show their age; manual declarations are identified.

Work

Read from top to bottom: proposals and notices, filters, Waiting for you, Working now, chips to start or queued, To merge, and milestones.

A chip shows its title, state, execution and review attributes, explanation, then actions. Open Details to inspect the brief and change allowed choices before starting. Running summaries are read-only; eligible desktop Claude sessions offer confirmed model or effort changes for the next turn.

Load

Read the model × effort table, then provider limits and budgets, context windows, and weights with recent distribution. Usage is used, not remaining. Context measures a session’s filled context window; it is not the account budget.

Check the source and age before trusting a number. Unknown capacity is not free capacity. Refresh provider measurements before a large batch.

Read labels with colours

Cards group work; pills group attributes. Green marks running work, amber calls for attention, red marks failure or blocking, and violet marks delivery. States have words as well as signs. Effort uses filled blocks and its name, such as ▰▰▱▱ medium.
