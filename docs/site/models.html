Effort is a reasoning preference, not a token budget. Work-mode defaults start R0–R2 at medium and R3–R5 at high. Codex lane minimums, sensitive minimums, and model caps still apply. The panel never offers max.

The balancer fills only omitted executor, model, effort, and reviewer fields. Explicit choices stay. Weights combine with lane scoring, fresh margin, and current load on the model; they are preferences, not permissions. Unknown capacity gets a conservative score.

Above a provider’s critical threshold, open choices strongly favour another allowed provider. This is not a hard spending stop. Manual budgets are declarations, not measured capacity. The destination has its own advisor; the balancer does not choose it.

Advisor or reviewer?

Auditor = Claude Code advisor
The working Claude model may consult another model at decision points. This is separate from independent review.
Reviewer
Checks the result. Claude work normally crosses to Codex, and Codex work to Claude, subject to routing rules. Sensitive work uses a different Claude model and human review.

On API Claude, the auditor applies per run. In desktop or ordinary terminal sessions, the owner types /advisor <model>; this changes the user default across sessions, so use /advisor off when done. It is unavailable in the cloud. Fable may require account consent and bill extra usage.

The stored advisor table follows Claude Code, not the Messages API (source dated 11 November 2026). Unknown or unsupported pairs block starts. In chipManager, fable resolves to claude-fable-5-2; do not rely on the host's model alias.

Fable directs; workers deliver

In Settings → Work mode, director mode is From R3 by default; choose Off or Always when appropriate. A director on claude-fable-5-2 analyses the goal and proposes self-contained child chips. It plans rather than routinely writing the code itself.

Fable 5.2 needs Claude Code 2.1.321 or newer. The doctor warns about older versions. Its default effort is high, with xhigh available explicitly; Fable 5.1 remains selectable as claude-fable-5-1.

  • Approve each child. Starting a director does not authorise its children, settings changes, or sessions outside chips. It cannot act as its own independent reviewer.
  • Constraints only tighten. Children inherit sensitivity, the R4/R5 lane floor, LAN-data restrictions, allowed providers and the parent's destination from stored records. These are checked at creation and start. Later edits to the parent cannot loosen an existing child's constraints.
  • No recursive directors. Depth is one. Defaults are 8 children and 2 re-plans; limits are configurable. A director in attesa-figli (waiting for children) frees its parallel slot. Discarding it also discards children that have never started.
  • Launch path. Use desktop when the starting session's tier permits it; otherwise the subscription CLI lane uses the explicit model ID. API keys, tokens, credential helpers, gateways or unreadable settings sources, including managed policy, block that subscription path.
  • Fallback is your choice. If Fable is unavailable or not allowed by project rules, the chip waits. Choose Run director on Opus explicitly. There is no automatic API/cloud diversion or second launch after an uncertain start.

Explicit chip choices come before director/chain defaults, work-mode defaults and balancing weights. Launch guards always apply. For local text writing, configure a chain writer; ordinary R0 children default to Haiku.

Claude mandates may name enabled baseline skills for the role. caveman, once enabled, also changes the answer style of every session by its own hooks; the work-mode switch only decides whether a mandate names it. The mattpocock-skills setup chip is never routed by balancing to Codex, the cloud or API credits: it runs on Claude, locally and interactively, lane R2 or above. Read the baseline skills guide.

Local & external providers

These are separate text executors: they receive the confirmed text, with no repository access, tools, files or project background. Their output is a draft for Claude to review.

Provider connections in 2.2.0
ProviderConnection and limits
OpenRouterConnect / Get the key opens its key page. Key verification is separate from model discovery. PKCE sign-in is not in 2.2.0: the host cannot write a native sensitive option.
Qwen APIAlibaba Cloud Model Studio: international (default), China or US. US requires a workspace URL matching the documented host pattern; a region choice alone is not enough.

Ollama / LM Studio / vLLMLoopback only: localhost, 127.0.0.1 or [::1]. Default endpoints are http://localhost:11434/v1, http://localhost:1234/v1 and http://localhost:8000/v1 respectively. Ollama needs no key; LM Studio and vLLM accept optional keys.
FreeLLMAPIKeeps its separate executor, loopback proxy, required key, allowed catalogue models and guided Docker setup.

Enable each provider for each project: none / R1 / R2 (Off means none). R1 permits R0 and R1 text; R2 also permits R2. Use low effort and Claude review. Sensitive work is refused at every level. Compatible providers need an explicit model; the balancer never chooses them.

The LAN-data filter and 1,500-character text cap apply to every non-Claude writer, including loopback. The filter rejects patterns such as emails, IP addresses, credentials, .env, storage/ and environment assignments. A local server can proxy a cloud model. Rewrites are checked as one combined prompt, including the draft and feedback; oversized input stops rather than being cut.

In Settings → Connections, Connect / Get the key opens the provider's key page. Paste keys only into native sensitive plugin options through /config; the panel never collects them. Check makes a cheap request on click. Detect local servers lists models on default loopback ports. The executor checks the catalogue before each run and refuses redirects and tool-call responses. LAN server addresses are not in 2.2.0.

Director → writer → reviewer → rewrite

A director can propose a text chain with catena: true; a standalone proposal can do the same. Each step is an ordinary chip requiring the owner's approval. Configure 1–3 review rounds, followed by the final rewrite and a Claude applier.

Chain presets
PresetWriter and reviewer
Director + local writerOllama qwen3 → Opus 5.5 review. The provider must be opted in and the model available.
EconomySonnet 5.5 → Opus 5.5 review (the default).
QualityOpus 5.5 → Fable 5.2 review.

dopoConsegna releases the next step only after delivery with an artefact. Ordinary dipende still waits for completion. Versioned text files live under artefatti/<chain>/<round>-<role>.md in the data folder, with path checks, a 60,000-character artefact limit and checked references. A rewrite receives draft vN plus the feedback on vN; Claude steps get artefact paths, while external writers get the combined text.

Only the Claude applier changes the repository. Writers and reviewers deliver text. Codex review is read-only and never applies it. Treat writer output as untrusted; the applier accepts or rejects it. The director does not replace independent review.

Chain steps run locally only. API-lane and cloud chain steps are blocked in 2.2.0. Sensitive goals cannot become chains. External writers also stop if a draft or feedback contains sensitive text, project rules cannot be read, the LAN-data filter fails, or the combined prompt exceeds the cap. The writer is never silently switched.

Child and round limits still apply: a chain needs room for all its steps. The panel shows artefacts and costs by role.

Count completed tasks

Compare cost per accepted result: planning + writing + review + rewrites + failed attempts. A single Opus session can cost less for a small, tightly coupled task; a director adds planning and handoff work. Keep required review in either comparison.

The panel separates plan, estimated, observed, unknown and free costs from each chip's own record. Local compatible-server calls are recorded as free, remote ones as unknown; that label does not measure electricity or any service behind a local proxy. Unknown is not zero.

Optional director-tree and chain dollar caps are soft. Where API reservations apply, a chip counts the higher of its reported cost and reservation; unknown spend consumes the reservation. The last step may overrun by what it spends in its own turn. Once the cap is exhausted, no further eligible group step starts.

Chain steps cannot use the API lane in 2.2.0: their cap checks recorded dollar costs and cannot hard-limit subscription use. A step on a remote OpenAI-compatible provider does not start under a chain or director cap, because its cost is not reported and the cap could not count it; a local server is free and runs. A project can only lower these caps, never raise the account's. Do not treat the cap as a provider billing limit. API Claude budgets also need a Console workspace limit for a hard spending boundary.
