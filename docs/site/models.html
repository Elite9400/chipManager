Effort is a reasoning preference, not a token budget. Work-mode defaults start R0–R2 at medium and R3–R5 at high. Codex lane minimums, sensitive minimums, and model caps still apply. The panel never offers max.

The balancer fills only omitted executor, model, effort, and reviewer fields. Explicit choices stay. Weights combine with lane scoring, fresh margin, and current load on the model; they are preferences, not permissions. Unknown capacity gets a conservative score.

Above a provider’s critical threshold, open choices strongly favour another allowed provider. This is not a hard spending stop. Manual budgets are declarations, not measured capacity. The destination has its own advisor; the balancer does not choose it.

Advisor or reviewer?

Auditor = Claude Code advisor
The working Claude model may consult another model at decision points. Only documented model pairs are allowed. It is not the independent branch review.
Reviewer
Checks the result. Claude work normally crosses to Codex, and Codex work to Claude, subject to the routing matrix. Sensitive work uses a different Claude model and still requires human review.

On API Claude, the auditor applies per run. In desktop or ordinary terminal sessions, the owner types /advisor <model>; this changes the user default across sessions, so use /advisor off when done. It is unavailable in the cloud. Some plans require Fable consent, and Fable may bill extra usage.

Codex executor: a Claude coordinator passes a brief to codex exec. Work mode selects workspace-write or read-only; Claude handles the commit. Codex reviewer: always read-only. One machine lane serializes Codex work, and waiting reviews take priority.

Fable directs; workers deliver

New in 2.2.0 — planned

The following is the corrected F13 design, not a control available in this worktree.

A director chip on claude-fable-5-2 analyses the goal, plans it, and proposes self-contained worker chips. The default is R3+; off and sempre (always) are also planned. It normally plans rather than writes code.

LaneWorker
R0Configured local writer; otherwise Haiku 5.5.

R4–R5Opus 5.5 with independent Claude review. If Fable is the director, it cannot also review that work; a conflicting chain must be resolved without relaxing review.
  • You approve every child. Approving the director does not approve children, settings, or direct starts.
  • No recursive directors. Children inherit sensitivity, minimum lane, data constraints, and allowed providers from records, not prose. Planned defaults: 8 children and 2 re-plans maximum. A director waiting for children does not occupy a parallel slot.
  • Launch path. Desktop when the starter’s tier permits it; otherwise a subscription CLI lane with explicit model ID. API credentials, helpers, gateway settings, or unverifiable settings sources block that subscription path.
  • No silent fallback. If Fable cannot start, the owner may explicitly choose Run director on Opus. Never divert to API/cloud, or retry on Opus after an uncertain start.
  • Compatibility. The plan requires Claude Code ≥ 2.1.321. Its own fable alias resolves to claude-fable-5-2; do not assume the host alias does. Start Fable at high; choose xhigh explicitly when useful.
  • Review and advisor differ. Planned branch-review pairs include Fable 5.2 ↔ Opus 5.5. A Fable 5.2 executor accepts only Fable 5.2 as its Claude Code advisor. Mythos IDs are recognised in the plan but not enabled.

Planned precedence: explicit chip choices → pipeline/director defaults → work mode → balancing weights. Guards win over every level.

Local & external providers

Available now: FreeLLMAPI is a separate text executor. It needs project opt-in, a key, allowed catalogue models, effort low, and Claude review. R0–R1 are allowed at level R1; level R2 also permits R2. Title + brief is limited to 1,500 characters. It gets no repository, tools, files, or project background. Its result is a draft, not an automatically applied edit. DeepSeek currently supplies balance measurements; it is not a direct chip executor.

Plan → write → review → rewrite

New in 2.2.0 — planned

A director builds ordinary, owner-approved chips for a writer, an independent reviewer, and 1–3 review/rewrite rounds. Proposed presets are Director + local writer, Economy (Sonnet writer / Opus review), and Quality (Opus writer / Fable review). The director cannot review its own plan.

The corrected hand-off uses dopoConsegna: delivery with a versioned artefact can release the next pipeline step. Ordinary dipende still waits for completion. A rewrite receives draft version N plus feedback for that same version; an oversized combined prompt stops instead of being silently shortened.

Writer output is untrusted. A Claude applier accepts or rejects text and applies it to the repository. A Codex reviewer supplies read-only feedback and never applies the text. Child, re-plan, round, and measurable API chain-cost limits stop the chain.

Count completed tasks

Compare total cost per accepted result: planning + writing + review + rewrites + failed attempts. A cheap draft needing several repairs can cost more than one good session. Keep plan usage, API dollars, and local compute separate; a local writer may avoid provider fees but still uses hardware and time.

A single Opus session can be cheaper for a small, tightly coupled task with little parallel work. A director adds planning and hand-off overhead; use it when splitting the work helps. Keep required review in either comparison.

F13 plans separate role costs labelled estimated, observed, or unknown. Child costs must come from their own records; current-session usage cannot stand in for the chain. No guaranteed savings or unverified model prices are assumed here.
