The five rules

  1. Propose; do not self-start. Use suggerisci_azione, one reviewable result per chip. Never start, merge, or close on your own.
  2. Write a self-contained brief. Include goal, files to read, scope, constraints, a checkable finish, and verification commands. No “as discussed”. Put spec paths in the brief, not only in piano.
  3. Respect lanes and data boundaries. Set the lane; explicitly mark sensitive work R4/R5 and sensibile: true. It stays local, Claude-authored and Claude-reviewed. Never include secrets or personal data in a brief.
  4. Read resources before a batch. Call risorse_agenti; regole.lette: false means no starts. Use allowed models and efforts. Leave choices out when balancing should decide. Depend only on work that must complete first.
  5. Report delivery and review. Use aggiorna_azione with the exact action ID and current attempt token. Delivery is not completion. Propose settings or weights only when the user asks; owner review still applies.
