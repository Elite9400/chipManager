Install

You need Claude Code and a session opened in a Git repository. Fable 5.2 needs Claude Code 2.1.321 or newer. Terminal workers also need node, git, and claude on PATH; Codex work needs codex.

Run these in your system terminal:

claude plugin marketplace add Elite9400/chipManager
claude plugin install chip-manager@chipmanager --scope user
Choose one installation scope
ScopeUse it for
--scope userYour projects; the usual choice.
--scope projectThis repository, shared through its committed .claude/settings.json.
--scope localThis project, only for you; .claude/settings.local.json is not committed.

Replace user in the install command with project or local when needed. Accounts, keys, and budgets remain personal in every scope.

In desktop: + beside the prompt → Plugins → Add marketplace → Elite9400/chipManager → Add plugin.

In every open Claude Code session, run:

/reload-plugins

Then reopen the panel with /chipmanager if needed.

Walk through setup

/chipmanager --setup
  1. Language. English, Italian, Spanish, French, German, or Brazilian Portuguese.
  2. Providers. Allow only the providers you want this project to use. Compatible text providers are off until you choose R1 or R2 for this project; local servers must use loopback.
  3. Sign-ins. Check Claude, Codex, and GitHub. Follow the offered sign-in steps for the tools you use.
  4. API keys. Optional. Enter them in the plugin’s sensitive options through /config. Setup shows only set or missing.
  5. Limits. Set warning and critical thresholds. For API Claude, set its account budget and per-run cap.
  6. Work mode. Choose default effort, parallel work and review preferences. Director mode defaults to From R3. Check chain presets and baseline skills here too; installing a skill is a separate, confirmed click.
  7. Summary. Review the draft and press Apply.

You can skip steps and return later. A settings proposal from a session opens setup at the summary. Baseline skills show their source, approved commit, data flow and hooks before installation; TokenEconomizer is experimental and off by default.

Most settings wait for Apply. Sign-ins, connection actions, manual budgets, and accepted weight proposals take effect separately. See what writes immediately.

Give the project rules

The project must have a complete .claude/routing.json (or its configured replacement). It defines allowed models, efforts, reviewers, and Codex lanes. Setup does not create this file.

Ask your project maintainer or Claude to prepare it using the routing example in the README. Include every required section and a reviewer row for each model you intend to use. Review those choices, then refresh the panel. Missing or unreadable rules block starts.

Review, then start

Ask Claude: Split this into small actions and suggest them in chipManager. Open Details on the first chip. Check the brief, lane, model, effort, reviewer, and destination. Choose Start.

Wait for delivery, review the result, and merge or mark it done. Use Start all once the proposed batch looks right; it confirms the plan and queues work that must wait.

Check the setup

/chipmanager --doctor

The doctor check changes nothing. Read each finding; repairs and sign-ins require your confirmation. For unsafe data paths, it can offer a verified copy to the safe default folder while keeping the old folder. See Doctor & reports if a start remains blocked.
