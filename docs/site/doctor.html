The doctor diagnoses your setup without changing it. Each finding explains what failed and what you can do next.

Run the doctor

/chipmanager --doctor

Use Recheck after a repair or sign-in. A successful check is evidence about these checks, not a guarantee that every possible error is absent.

What it checks

Diagnostic coverage
AreaFindings
ConfigurationUnreadable JSON, missing backups, unknown fields, invalid work mode, invalid project values, and project restrictions looser than account limits.
Data & spendUnsafe data/config/spend paths, Git working trees, links or junctions, and a development build’s old per-project spend register.
API runAPI lock, unreadable lock, and leftover key files.
ActionsActions without a project, or referring to an unknown project.
Access & hostRelevant Claude, Codex, and GitHub sign-ins; settings that interfere with API Claude or advisor behaviour. Panel checks also report host/connection findings.

Some findings have no repair button. The doctor does not remove unknown fields, silently delete keys, or rewrite host settings.

Confirmed repairs

Restore
When configuration is unreadable and a valid backup exists, restore the newest valid one among the three kept copies. Counters advance so stale board writes and old weight undos cannot replay.
Archive
Rename the development build’s per-project spend register to an archive. It is preserved, not overwritten.
Release
Ask to release the API lane; the helper checks that the run, descendants, and key file are gone. Clicking cannot free an active run.
Sign in
Follow the offered Claude, Codex, or GitHub flow, then recheck.

Repairs need confirmation and the doctor runs again afterward. Restore affects configuration, not repository history.

Report codes, not project data

Copy report copies the human-readable findings. Report to chipManager builds a separate redacted report and shows its full text before asking permission to submit.

The GitHub report contains known finding codes and allowlisted metadata: plugin/host version, surface, and known settings field names and types. No setting values, paths, project names, branches, briefs, code, keys, or account details are included.

After your explicit yes, it can create an issue in Elite9400/chipManager using gh, or open a prefilled GitHub page where you submit it. If opening fails or the URL is too long, use the offered copyable text. Never paste private project details into an issue.

Current limits

The junction-aware path change and one-click data relocation are planned separately in F13.0; this worktree still rejects links in ancestor paths. Fable 5.2 compatibility checks are also planned. See junction troubleshooting.
