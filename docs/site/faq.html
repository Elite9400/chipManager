Troubleshooting

Why will nothing start?

Read the chip’s reason. Common causes are missing or partial routing.json, an unreadable config, an unavailable reviewer, a disconnected provider, or an incomplete dependency. Run /chipmanager --doctor, then refresh. Setup does not create routing rules: see Give the project rules.

My data folder uses a junction.

Junctions above the data root, such as a redirected home or .claude folder, are allowed. The resolved data path must be outside repositories; links at or inside the data root are refused.

Run the doctor. Where offered, Move data… copies to the safe default folder, verifies the files and changes the project configuration. The old folder is kept. Skipped links need explicit acceptance. Active work, a non-empty destination or changed configuration stops the move. A CHIPMANAGER_DIR override must be corrected separately. Read the path rules.

I updated, but a session looks old.

Run /reload-plugins in every open Claude Code session, or restart them. Installing or updating does not replace code already loaded by a running session. Reopen /chipmanager afterward.

My login expired.

Open /chipmanager --setup or the doctor and use the relevant sign-in action for Claude, Codex, or GitHub. Complete the browser/device flow, then Recheck. If the CLI is missing, follow the offered preparation or copyable command. Never put login tokens in a chip.

Fable 5.2 is not available.

Use Claude Code 2.1.321 or newer and check account access, consent and project routing for claude-fable-5-2. The doctor warns about an older host. A director uses desktop when the starting session's tier allows it, otherwise the subscription CLI path. Conflicting credentials or unreadable settings block that path.

Choose Run director on Opus explicitly if appropriate. There is no silent switch to API/cloud or second launch after an uncertain start. Fable 5.1 remains selectable. Read about director mode.

My local server is not found.

Start Ollama, LM Studio or vLLM, make a model available, then use Settings → Connections → Detect local servers. Detection checks their default loopback ports: 11434, 1234 and 8000, with /v1/models. Only loopback endpoints are accepted; LAN addresses are not in 2.2.0.

Discovery alone does not enable a provider: choose the project's R1 or R2 level, Apply, and use a catalogue model. Detection sends no key, so a server requiring authentication may not appear. Optional LM Studio/vLLM keys go in sensitive plugin options. For FreeLLMAPI, check the loopback proxy, required key, project opt-in and allowed model.

Why will the next chain step not start?

The previous step must deliver a versioned artefact, not just finish its session. A rewrite needs the matching draft and feedback. Check approval, child/round limits, cost cap and local destination: chain steps cannot run on the API lane or in the cloud in 2.2.0.

External writers stop on sensitive text, unreadable rules, LAN-data patterns or a combined prompt over 1,500 characters. The prompt is never silently shortened. Read the chain handoff.

Why was a baseline skill disabled?

A mod-installed skill must match its approved revision and hooks and have enable consent recorded. The session-start check disables mismatches and warns you. Inspect the source and approval before enabling it again. An unreadable plugin listing means unknown; managed plugins are locked.

TokenEconomizer is experimental and remains off until its safe configuration passes and you give a second consent. Its user-installed copies are left alone by the installer and start check. Read the installation steps.

Why does Help only show addresses?

Help has replaced Legend, but the 2.2.0 code marks the documentation site unpublished. It shows copyable addresses and opens nothing. You can read this downloaded guide locally; publication needs the repository owner to enable Pages.

Why is a delivered chip still open?

Delivery means a result is ready, not merged. Automatic completion needs a registry task linked by branch and issue. Without that link, or in a shared folder, inspect the result and use Mark done. Ordinary dependent chips wait for completion.

The start is uncertain. Should I retry?

Check the existing session or attempt first. A lost launch reply may hide a successful start. The launcher avoids duplicate workers; read the status and reason before another start request.

Why is API Claude blocked?

Check the key in sensitive plugin options, account budget, per-run cap, project limits, and one-run-per-machine lock. Inherited API credentials or conflicting host settings can block the lane. The doctor names the source without exposing values. Do not force-delete a live lock.

Why did my docs task become R4?

The detector matches words starting with auth, including author. Reword a false match in a non-sensitive brief. Work on authentication, permissions, or personal data must keep R4/R5 and explicit sensitivity. See detection limits.

I discarded the draft. Why did a change stay?

Connections, manual budgets, and applied weight proposals write through their own actions. Discard changes affects only the Settings draft. Weight proposals have a separate Undo. See when settings write.

What works offline?

These pages need no JavaScript, external fonts, or network resources; open index.html from a downloaded docs/site/ folder. Source links to GitHub need a connection. The local board also has no remote resources, but Claude/Codex sessions, sign-ins, probes, and GitHub operations need their services.

Still blocked?

Run /chipmanager --doctor. Read its findings and confirm only the repair you want. To report a bug, use Report to chipManager and inspect the codes-only preview before submitting. Read what the report includes.
